# S04 — техническое вскрытие Lot A

**Дата:** 7 ноября 2026, Asia/Yekaterinburg. **Самопроверка: PASS; независимый QA ожидается.** Ветка `s04-lot-a-opening`, без коммита/переключения/отправки.

## Реализация и границы

E у «Стола вскрытия» открывает OpeningScreen. До покупки и после проигрыша аукциона он сообщает, что сначала нужно выиграть A, и не создаёт строк скрытого содержимого. После победы сообщение S03 направляет к столу.

GameState — единственный источник состояния и словаря `item_zones` (item_id → zone):

| Состояние | Допустимое действие | Результат |
|---|---|---|
| LOCKED | выиграть аукцион A | SEALED |
| SEALED | cut_seal(), «Срезать пломбу» | UNSEALED |
| UNSEALED | open_lid(), «Открыть крышку» | SORTING |
| SORTING | assign_item(id, zone) | одно назначение; после четвёртого COMPLETE |
| COMPLETE | открыть/закрыть итог | сохранённое распределение без изменений |

Предметы читаются из `data/lots/lot_a.tres.future_items` в порядке ресурса, названия и исходные состояния нигде в UI/логике не зашиты. После крышки четыре строки показывают `display_name` и `initial_condition`; следующая становится активной после назначения предыдущей. COMPLETE повторяет оба значения в итоговом распределении. В API также проверяется ресурсный порядок. До крышки `get_opening_items()` возвращает пустой массив. Ресурс не изменялся.

Методы проверяют владение/ожидаемое состояние, четыре непустых уникальных ID ресурса, отсутствие повторного назначения, очередной ID и три допустимые зоны: «быстрая продажа», «рабочий стол», «хранение». Любая зона допустима, S04 ничего не оценивает. Назначение — только запись в словарь и журнал; деньги не меняются, продажа не создаётся.

Guard `_opening_resolving` выставляется до перехода/сигнала и снимается после него. Состояние/назначение изменяется до `state_changed`. Вложенные cut/open/assign блокируются, в том числе назначение следующего ещё допустимого предмета. Вызовы вскрытия также блокируются во время завершения аукциона. F4 не может сбросить незавершённую транзакцию из вложенного сигнала. Кнопки зон привязаны к ID конкретного предмета, поэтому повтор её сигнала не назначает следующий предмет.

Workshop использует общий `_active_modal()` для блокировки движения/обзора/E/debug-команд и Esc; `_show_modal()` открывает только одну форму за раз. Esc/кнопка закрытия ничего не сбрасывают. Повторное E восстанавливает текущую стадию/назначения, COMPLETE повторяет итог. F4 в мастерской снимает владение, возвращает LOCKED, очищает назначения/журнал и возвращает 750. Перезапуск тоже начинает новую runtime-сессию.

5. Неизвестный ID/зона, внеочередной ID, повторное назначение и повреждённый ресурс с повторяющимся ID отвергаются; ресурс после диагностической проверки восстановлен в памяти без записи на диск.
6. Повторный сигнал кнопки, повторные API и reentrant-вызовы из state_changed не продвигают состояние/очередь; callback видит уже обновлённый словарь.

8. COMPLETE появляется только после четвёртого назначения, все названия/зоны есть в итоге, дальнейшие действия отвергаются.
9. Распределение не изменяет 170, включая «быструю продажу».
10. F4 из мастерской на LOCKED/SEALED/UNSEALED/SORTING с частичным назначением/COMPLETE полностью сбрасывает состояние; новый цикл работает. ## Ручное воспроизведение и ограничения

Запустить проект → E у стола до покупки (LOCKED) → закрыть → выиграть A с пределом 580–620 → закрыть аукцион → E у стола (SEALED) → пломба → крышка → четыре назначения в любые зоны → COMPLETE. Закрывать и открывать можно на любой стадии. F4 после закрытия формы начинает новый цикл. Подробные шаги и тестовые команды — в README.

Это самопроверка разработчика. Независимый QA S04 ещё не выполнен; исторический PASS S03 не заменяет его. Программное наведение и runtime-события не заменяют непрерывный ручной обход живого игрока. Оконный тест начинался с подготовленного положения у стола; обычный путь покупки отдельно покрыт регрессией S03. Нестандартные разрешения и доступность не оценивались; форма поддерживает вертикальную прокрутку.

Нет общего инвентаря, физической переноски, drag-and-drop, фактической продажи, очистки/оценки, новых ассетов, S05+, процедурной генерации или сохранений. Назначения живут только до F4/рестарта; правильность выбора зон не оценивается.
